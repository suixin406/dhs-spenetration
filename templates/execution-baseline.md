# 授权安全测试执行基线

知识库中的旧简称统一映射到本文件：

- `dig-scope`：本文件“范围与开场”“认证与对象测试”“换面纪律”；
- `src-value` / `src-value-hunting`：本文件“报告阈值”；
- `cors-vuln-report-priority`：本文件“CORS 判定”；
- `vuln-report-format`：`templates/vulnerability-report.md`。

## 1. 范围与开场

1. 网络目标先运行 `tools/scope_guard.py`，host、port、action、time 全部命中才继续。
2. 一次围绕一个已登记种子闭环：存活面、JS/API、身份面、对象面、上传与逻辑面。
3. 外部测绘只补当前范围缺口；新发现资产先加入授权记录，不自动扩展范围。
4. 随机子域命中同一解析时按泛解析处理，停止字典喷洒。

## 2. 认证与对象测试

1. 登录表单先读前端字段、限流和真实认证协议，不无界试密。
2. 密码重置、改绑、邀请、OAuth/OIDC 回调和 MFA 单独建测试矩阵。
3. 有会话时建立对象图：自己的对象、他人对象标识、租户标识、列表与详情对应关系。
4. 默认使用只读差分证明越权。写操作只针对可恢复的自有测试对象；不可恢复动作属于 destructive。

## 3. 全类型矩阵

对存在输入差分的面按技术栈检查注入、SSRF、XSS、文件/路径、反序列化、请求走私、缓存、竞态和业务逻辑。没有对应输入面时记录 N/A 及理由，不为了勾表向随机路径喷 payload。

## 4. 换面纪律

同类技术连续三次无有效信号即复判指纹并换面。资产、身份、对象、文件、协议、配置和供应链之间切换；不在两个失败面之间反复横跳。

## 5. 报告阈值

- 只有可重复的安全影响和原始证据才能进入“已确认发现”。
- 版本、Banner、Schema、缺少单个响应头和无影响的错误信息属于线索，不直接定漏洞。
- 凭据/密钥必须用假值对照证明服务端确实接受；报告中脱敏。
- 数据访问按最小样本证明，禁止为统计数量批量拉取个人数据。
- 结论区分“已确认”“受限验证”“未验证假设”。

## 6. CORS 判定

仅缺少或错误的 CORS Header 不单独报告。需要证明攻击者控制的 Origin 能在受害者会话上下文中读取敏感数据或完成有影响的状态变更，并排除无凭据公开数据。
